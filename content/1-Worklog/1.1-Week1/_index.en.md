- Successfully installed Kiro on the local computer.

- Understood how Kiro supports requirement analysis, specification development, planning, code generation, and debugging.
- Completed the Module 1 learning content.
- Prepared the initial foundation for developing the project proposal and system design in the following week.

## Challenges encountered

- AWS includes many new services and technical terms, so additional time was required to become familiar with them.
- It was initially difficult to determine when each AWS service category should be used in a real system.
- The differences among the root user, IAM user, and IAM role were sometimes confusing.
- There was limited experience in monitoring cloud costs and managing AWS resources.
- The Kiro interface and workflow were new.
- It was difficult to write requirements clearly enough for Kiro to return suitable results.
- Kiro has usage limitations, so its credits need to be used carefully for larger tasks.

## Solutions

- Take notes and classify AWS services by their main purposes.
- Use the root user only for initial administrative tasks and prefer an IAM user for daily work.
- Learn about AWS Free Tier, the Billing Dashboard, and AWS Budgets before creating cloud resources.
- Practice with Kiro on small sample projects before applying it to the main project.
- Break large requirements into smaller tasks and clearly describe the expected input, output, and constraints.
- Review and verify the content suggested by Kiro before using it.
- Avoid depending entirely on Kiro; the developer must still understand the architecture and source code.
- Use Kiro credits appropriately, prioritizing requirement analysis, planning, code assistance, and debugging tasks.
